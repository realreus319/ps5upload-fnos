# PS5Upload for fnOS

飞牛原生 Docker FPK 薄壳，使用 PS5Upload 官方镜像，Host 网络，端口 19113。不增加业务后台，不挂 Docker Socket，不加入 docker 用户组，不用脚本生成 Compose。

安装配置：游戏目录、PS5 IP（可选）、临时安装包目录、应用数据目录（可选）。目录通过文本框填写宿主机绝对路径，默认游戏目录使用 PS5Upload 共享目录，默认临时目录使用应用数据目录。指定临时目录时，程序使用其下的 ps5upload-staging 子目录。外部目录需要预先存在，应用用户必须拥有读取或写入权限；不自动修改用户文件权限。游戏目录只读，应用状态默认保存在飞牛应用数据目录（TRIM_PKGVAR），直接读写挂载到 `/data`；填写已有的宿主机绝对路径（例如 `/vol1/1000/ps5upload/data`）可覆盖默认位置。目录必须可由应用用户读写。0.1.3 及更早版本使用具名卷 `ps5upload-fnos_ps5upload-data`，本版本不自动迁移或删除旧卷；已有用户应先停服务、备份并复制旧数据，再升级。服务无密码，开放 IPv4，仅供可信网络使用，禁止直接暴露公网。

安装向导字段直接进入 Compose，参考 WechatOnCloud（https://github.com/Gloridust/WechatOnCloud/tree/main/fnos/woc）及 Transmission（https://github.com/conversun/fnos-apps/issues/290）。镜像更新由飞牛 Docker 管理器负责。配置保存后是否重建及重建时参数是否保留，需要真机验证；如果系统没有重建，不应宣称配置已生效。当前不实现图形化选择器，不使用安装后授权来冒充安装向导选择器。CI 仅验证真实镜像、模拟向导参数、读写与数据保留及 FPK 构建。真机安装、权限、更新和配置变更仍待验证。发布包通过 CI 容器测试与官方 fnpack 打包后上传至 Releases。

## 目录校验

安装与配置阶段仅检查非空自定义目录的格式、是否明确不存在或不是目录，错误时返回非零并写入可用的 TRIM_TEMP_LOGFILE。v0.1.6 移除读取、写入、访问权限的前置校验；无法确认目录状态时交由 Docker 挂载检查，不改变任何目录权限或容器运行身份。留空不检查系统尚未创建的默认目录。Compose 禁止自动创建绑定源目录。原生向导未公开宿主机路径实时校验接口，因此能够确认不存在的目录在安装前置阶段报错，不保证在点击下一步时直接显示字段内错误；实际回调时序与提示仍须在 fnOS 真机确认。

## 桌面入口（x86 候选版）

单个官方 Docker 容器，Host 网络不变。FPK 内置静态 Rust 代理，Compose 只读挂载并用它作为启动包装器；包装器启动原始 /ps5upload-engine 并监听 Unix Socket，不修改镜像、不增加容器或宿主机服务。Docker 停止时转发 TERM 并等待原始引擎退出。网关 Socket 权限 0660，不自动开放给所有本地用户。飞牛网关是否可访问此 Socket 需要真机确认。HTTP 反代保留原始 Host/Origin 与上游安全响应头，管理员请求通过，其他请求拒绝。直连 URL 改为 http://NAS-IP:19113/app/ps5upload/，包传输路径由官方 engine 处理。当前 x86 静态二进制，ARM 未打包。真实 fnOS 的网关身份、路径权限和启停仍待验证。禁止将无密码的 19113 暴露公网。

## v0.1.7 运行身份

FPK 用户身份保持 package。容器内一个仅负责启动、降权和转发退出信号的监督进程以 root 运行，限制为 SETUID/SETGID/KILL 三项能力；Rust HTTP 网关始终使用飞牛包用户，官方 Engine 使用独立的非 root UID/GID。默认应用数据目录时自动使用包身份；自定义应用数据目录时自动使用 1000:1000；高级设置可分别覆盖 UID/GID。Engine 额外保留包 GID，便于访问已授权的默认目录。临时目录留空时与实际应用数据目录一致。不会 chown/chmod 任何用户目录，也不会复制、删除或迁移数据。混用默认目录与不同 UID 时仍需确保实际 ACL/权限允许访问，已有身份密钥的所有者也须匹配。CI 使用私有 0700 自定义目录复现权限问题，飞牛真实 ACL 与网关仍需真机确认。
